# **Common Issue: Large files failed to sync to GitHub**
## **Symptoms**

Running git push failed with an error that the repository contained files that were too large to upload.

## **Cause**

Raw_Data files (*.fastq) and alignment files (*.sam) from the SARS-CoV-2 Viral Genomics pipeline were committed to the repository, exceeding the recommended size limits.

## **Solution**

1. Added patterns such as Outputs/*.sam and Raw_Data/*.fastq to the .gitignore file so new large data files are not tracked.

        .gitignore

        echo "Outputs/*.sam" "Raw_Data/*.fastq" >> .gitignore

2. Removed already‑tracked large files from the index (but kept local copies) using git rm --cached:

        git rm --cached Outputs/*.sam

        git rm --cached Raw_Data/*.fastq

3. Cleaned the existing Git history to fully remove large files from all previous commits using git filter-repo:

        pip install git-filter-repo (if not already installed)

        git filter-repo --path Outputs/ERR7543893.sam --invert-paths

4. Committed and force‑pushed the cleaned history to update the remote repository:

        git commit -m "Clean history: remove large data files and update .gitignore"

        git push origin main --force

## **Prevention**

For future runs, store large FASTQ, BAM, and SAM files outside Git (in cloud or external storage) and only track scripts, configuration files and small datasets in the repository.
